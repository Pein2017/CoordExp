# Production-Shaped Smoke

This procedure supplies execution evidence, not a new approval layer. Use the
selected checkout's real launcher/config and current runtime. The active
scientific and compatibility owners define the behavior being preserved.

## Select the evidence boundary

An early risk-retirement slice exercises the few real seams that could invalidate
broad implementation. A final frozen integration smoke traverses every applicable
conclusion-bearing production stage and binds the result to that candidate.
Record unexercised risks as unproven; early success does not establish full
integration or scale readiness. A top execution-risk failure stops dependent
broad work, not unrelated tasks.

When process ownership or artifact production/finalization/readback changes,
make the first checkpoint the actual caller-to-terminal-consumer path. Include
shared versus process-local writes and reused helpers' lifecycle assumptions.
CPU-only authorization may substitute unavailable model/device computation, not
the real entry, process ownership, filesystem, serialization, finalizer or
consumer. It proves only the CPU lifecycle, not model numerics or collectives.

## Reduce workload, not the contract

Use production configuration with fewer samples and enough steps to reach the
named seams. Permitted reductions are fresh output location, sample/step limits,
shortened save/eval cadence with unchanged mode, and stability settings such as
zero loader workers. Preserve model, template, packing, maximum length, geometry,
optimizer/learning rate, decode, checkpoint mode and evaluation meaning unless
explicitly under test. Bind serialization to a checkpoint trained for it.

A final smoke crosses enabled save and evaluation boundaries. An early slice
crosses them only when needed for the named risk. For rank-dependent behavior,
include real multi-process work with intentionally different local loads and the
required collective order; single-rank or leaf tests cannot close that risk.
For server rollouts verify endpoint reachability and proxy bypass.

## Verify the terminal consumer

Select the applicable stages: data/encoding, packing/positions,
forward/backward/optimizer or rollout, checkpoint, parsing/scoring/evaluation,
canonical serialization and atomic publication, fresh reload and downstream
consumption, runtime identity and process exit.

- Reach the planned terminal step with complete rank coverage and real exit
  status; the first optimizer step or artifact existence is insufficient.
- When payload/load/resume/downstream behavior changes, start a fresh process,
  load the production-owned checkpoint, check promised model/adapter/auxiliary
  keys, shapes and dtypes, then execute a conclusion-bearing forward/evaluation
  at the feature owner's tolerance.
- Enabled evaluation must receive normal outputs and emit finite metrics in the
  current namespace. Bind authored/effective config, data/decode scope, batch,
  accumulation, save/eval cadence and packing identity.
- Distinguish metric-bearing outputs from truncated/parser-failure diagnostics.
  Exercise nonempty canonical serialization, publication, reload and the real
  consumer before expensive broad execution.

## Scale bounds

Before increasing data, ranks or GPUs, measure the relevant representative bounds:
forwards per sample/pack/rank including counterfactual work; wrapped/unwrapped
calls, collective sequence and optimizer mutation; cache/materialization passes,
bytes and I/O amplification; elapsed time, peak RSS and workers; rank/merged
artifact payload; process ownership, finalizer, cleanup and readback. For an
at-most-once operation include activation count, partial outcome and recovery
ceiling only when that protocol applies. Unknown or exceeded relevant bounds do
not establish scale readiness.

Report production identity, reductions, stages actually crossed, resources,
checkpoint/artifact/metric evidence, failures/skips and the exact claim supported.
Preserve unproven native stages rather than upgrading a CPU substitute to proof.
