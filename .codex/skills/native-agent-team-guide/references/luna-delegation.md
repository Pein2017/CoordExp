# Briefing Luna execution workers

For the supervising main: use the applicable example when an assignment crosses
configuration, training-caller or artifact-consumer boundaries. The parent
[guide](../SKILL.md) owns scope, routing, communication and acceptance; this
reference adds worked briefs, not another approval stage or universal template.

These examples come from bounded CoordExp work with observed
`gpt-5.6-luna/high` reducer and `gpt-5.6-luna/max` objective-check assignments.
They are reusable starting points for Luna workers, not measured family traits,
an effort ranking, or a reason to prescribe those settings for future tasks.

## Give the effective contract, not a task label

“Enable the default losses” leaves configuration inheritance and the meaning of
default unresolved. Supply the authoritative resolved configuration and approved
delta, rather than asking the child to infer intent from an old YAML or history.

Example brief fragment:

> Use the bound resolved configuration and apply only the listed changes.
> Report inherited effective values alongside the requested values; identify
> conflicting sources before implementing an interpretation. Verify the terms
> in the maintained objective caller, including masks and denominator, rather
> than proving only that configuration fields exist. The parent owns launch
> configuration reconciliation; this assignment does not authorize model calls.

In the observed work, the earlier CE-only recipe followed a lead exclusion and
parent-authored configuration. It was not a child omission of enabled terms.
The later brief supplied the explicit delta and parent checked actual execution.
Keep experiment-specific coefficients in the bound task, not in this reference.

## Name the real caller and legitimate zero cases

“Check that gradients and parameters change” can reject correct initialization
or pass an unused helper. Point to the actual hook, gather/reduction path and
optimizer/scheduler order. Ask for an independent expected result and the nearest
plausible incorrect implementation that the check must reject.

Example brief fragment:

> Reuse the maintained training caller. Identify where the check observes loss,
> backward, optimizer.step and scheduler.step. Check the actual global
> denominator against an independent formula; demonstrate rejection of a
> disabled term or wrong normalization. Permit legitimate zero hinge and
> initialization-dependent zero gradients. Use the LR actually consumed by
> optimizer.step: an LR0 call may advance moments without moving parameters.
> A positive-LR no-op must fail on a case with an expected nonzero update.

For a consequential ambiguous hook, request a short interpretation of the caller,
invariant and counterexample before integration. This is not a mandatory
readback-and-wait ritual for every edit. The observed first-two-update slice was
a task-specific bound, not a required number for every run. Leaf-test counts do
not substitute for the authorized real-entry evidence.

## Specify what compatibility promises

“Keep results compatible” can mean matching aggregates, schema compatibility or
exact historical bytes. Choose the required promise and consumer explicitly.

Example brief fragment:

> The historical entrypoint must reproduce the bound artifact byte-for-byte;
> matching summary metrics alone is insufficient. Keep new metadata in the new
> output. Load cohort membership from the frozen admission, independently of
> whether a cell was reused. Exercise old and new callers and reject a fixture
> that confuses reuse with membership. Return exact replay paths and results.
> If a downstream caller enriches a saved artifact, freeze the consumer-facing
> schema and compute/verify its integrity binding after the last write.

A child metadata addition preserved scientific aggregates but broke promised
whole-artifact replay; the parent removed it locally. Another boundary required
explicit retained-panel membership because reuse no longer identified that panel.
Do not demand byte identity when the real contract requires only semantic or
schema compatibility; numerical comparisons use the task's existing tolerance.

## Correct the brief and accumulate useful experience

When a child misses a semantic boundary, send the violated invariant, a concrete
counterexample and the required outcome. Repeating “be careful,” increasing
effort alone or appending the entire history does not resolve an ambiguous
contract. Let the child handle ordinary local repairs; take over a small coupled
integration fix when that is cheaper than another handoff. Do not impose a new
repair-count ceiling or silently expand the scientific assignment.

Use the existing task notes to retain only what changes the next brief:
original instruction, observed miss, correction and verified outcome. Separate
parent configuration/integration errors from child implementation mistakes.
Local import or fixture errors usually need ordinary tests, not another global
prompt rule. Reuse the lessons in subsequent briefs; skill and persistent-memory
edits still follow their authorization rules. Do not create a routine interview,
new ledger or capability benchmark to maintain this reference.
