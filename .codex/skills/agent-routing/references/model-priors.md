# Current Model Priors

> Time-sensitive empirical state for the `agent-routing` skill. The lead uses
> this reference when surface, model, or effort selection is material. Workers
> receive the selected route in their brief and do not load this file.

## Model Priors

| Model | Provisional fit | Important boundary |
| --- | --- | --- |
| Claude Haiku | Fast mechanical work, extraction, smoke tests, and bounded scans behind a verifier | Its detections can be trusted only when the verifier also checks the declared root or source inventory; its narrative diagnoses cannot. Read the receipt, not the summary |
| Claude Sonnet | Balanced bounded implementation and ordinary coding; use on a lifecycle slice only when one integrator owns the seam and the initial verifier enumerates every present, absent, failure, and compatibility path | A frozen interface alone did not make a full controller-to-merge lifecycle first-pass reliable; require structural acceptance including the historical field-absent path and avoid repeating expensive real probes across tests |
| Claude Opus | Cross-file integration, architecture seams, broad fixed-tree engineering certification, and source archaeology | Freeze and hash-bracket the target; its breadth repays latency when baseline debt, receipt reproduction, and lifecycle provenance all matter, but target drift invalidates certification rather than measuring model quality |
| Claude Fable | Core planning, architecture alternatives, and difficult decision discussion | Local task-class evidence is sparse; do not spend it on routine implementation |
| Codex Luna | Default bounded worker for evidence collection, feasibility, code/convention scouting, and mechanical checks behind a verifier; `high` is a practical ceiling for ordinary lanes | A verifier, frozen API, or disjoint files do not make crash consistency, durability, concurrency, schema compatibility, or a value crossing three or more lifecycle stages Luna-shaped; do not infer judgment fitness from low cost or automatically climb to `xhigh`/`max` |
| Codex Terra | Stable cross-file implementation ownership, persistence invariants, interface synthesis, integration, and contract closure | Retain structural verification and measure the real critical path: a green persistence contract can still hide an unacceptable O(n^2) append path |
| Codex Sol | Research reasoning, architecture trade-offs, silent-correctness review, conclusion-critical synthesis, and fixed-tree research-versus-infrastructure boundary audit; prefer `high` | Do not spend it on routine mechanical audit or overlapping judges; pair semantic review with deterministic counterexamples and a separately authorized runtime gate, and require a named unresolved uncertainty for `xhigh` |

Effort tunes depth within a model; it does not define the role or improve every
model monotonically. Treat model and effort as an interacting route pair. Start
at low for straightforward verified work, medium for ordinary bounded agents,
and high for cross-file reasoning or review. Use `xhigh` or `max` only for a
localized, consequential uncertainty that lower effort has not resolved.
When a capable model broadens scope, redesigns unnecessarily, or turns a
builder lane into an audit, tighten the brief or lower effort before escalating;
that is a different failure from insufficient reasoning depth.

For Codex worker lanes, use Luna as the natural first route while it remains
available: low/medium for mechanical work and high for deeper but still bounded
and verifier-backed scouting or implementation. Give one focused correction
before changing the route. Use Luna xhigh/max only for a demonstrated localized
depth gap; do not treat effort escalation as mandatory before changing roles.
Route to Terra/high for persistent cross-file ownership or contract closure,
and to Sol/high for silent-correctness risk, research judgment, or
conclusion-critical synthesis. Reserve Sol/xhigh for a named consequential
uncertainty that survived a narrower pass. The cost/capability differences are
current routing priors to test against receipts, not a permanent transitive
model ranking.

## Observed Differentiators

- A 2026-08-07 resumable natural-boundary support-shard implementation adds
  task-conditional evidence for the current Codex routes, not a matched model
  benchmark. Luna/high was effective for bounded source inventory and command
  discovery. Luna/max closed an isolated source-binding leaf after one focused
  correction to its volatile-field exclusion test; exact hashes and a
  deterministic verifier made that lane suitable, while the extra effort did
  not make it an owner of durability or the end-to-end consumer lifecycle.
  Terra/high handled a broader adapter integration slice but required a focused
  correction and lead closure after omitting lifecycle-critical execution and
  compatibility work. Sol/high was `accepted_first_pass` as the independent
  fixed-tree reviewer: its reproducible `HOLD` found that the legacy
  materializer could swap slot journals and publish before the unchanged merger
  gate, and that the real GPU receipt bound a superseded adapter. The repaired
  boundary then passed the same review plus a fresh exact-tree SIGTERM/resume
  gate. Routing consequence: use Luna/max only for a demonstrated localized
  depth gap whose full result is mechanically decidable; use Terra/high for one
  explicitly enumerated integration seam with a lifecycle matrix; use Sol/high
  after code freeze for high-consequence provenance and publication-boundary
  counterexamples. A successful reviewer `HOLD` is route acceptance, while the
  audited target remains rejected until repair and re-verification.
- A 2026-08-06 execution-evidence implementation supplied explicit
  verifier-backed dispositions across four heterogeneous lanes, so it informs
  task-shape routing without forming a model ranking. Luna/medium was
  `accepted_first_pass` for read-only source/convention scouting with exact
  line evidence. Terra/high was `rejected_or_escalated` for end-to-end
  crash-consistent journal ownership under the one-correction budget: its first
  contract-green delivery still had reload-invariant and O(n^2) append defects,
  and an independent audit later found orphan-attempt and lost-acknowledgment
  durability counterexamples. Terra closed the two targeted audit findings on a
  second follow-up and preserved the redesigned 1000-append path at about 0.571
  seconds, but that recovery is evidence for a narrower corrective lane, not
  first-route acceptance of the original broad persistence brief. Haiku/low was
  `accepted_after_correction` for a deterministic vocabulary-residue guard
  after the verifier exposed the wrong config root. Sonnet/high was
  `rejected_or_escalated` for the full controller/direct/worker/shard/merge
  lifecycle under the same budget: lead and independent review had to add
  controller-source validation, historical field-absent compatibility, strict
  identity shape and bool-schema checks, local sidecar verification, and tuple
  diagnostic projection. Routing consequence: use Luna for bounded evidence
  collection and Haiku for narrow guards only when source inventory is asserted.
  Terra and Sonnet remain plausible owners of persistence or lifecycle work, but
  a broad silent-correctness seam needs a smaller ownership boundary, an
  exhaustive failure/compatibility matrix in the initial brief, and an
  independent reviewer from the start. A completion or green focused suite did
  not substitute for lead integration acceptance in any builder lane.
- The same 2026-08-06 work supplied complementary fixed-tree reviewer evidence.
  Sol/high was `accepted_first_pass` for research-versus-infrastructure boundary
  audit: successive exact-tree audits found digest-consistent unknown research
  fields, false terminal sidecar binding, and later a free-form process-attempt
  research channel despite green suites. Each `HOLD` was a successful audit
  verdict, not an agent failure; bounded rechecks passed after the target was
  repaired. Opus/high was effective for broad engineering certification: it
  reproduced artifact, inference, baseline-failure, type, format, performance,
  and manifest receipts, found inaccurate format evidence and typed mechanics
  gaps, and used before/after aggregate bracketing. Its first certification
  attempt is `surface_failure` because the target changed mid-audit, even though
  detecting that drift was valuable; the stable three-file delta re-audit was
  `accepted_first_pass`. Routing consequence: use Sol/high for semantic boundary
  counterexamples after mechanical tests are green, and Opus/high when a wide
  fixed-tree certification must reconcile known baseline debt, lifecycle
  provenance, and numeric receipts. Freeze the target before either audit, keep
  audited-target `PASS/HOLD` separate from reviewer disposition, and treat a
  repair-followed-by-recheck as a new audit pass rather than a correction to the
  reviewer.
- A final Luna/medium completion-receipt lane on 2026-08-06 was
  `accepted_first_pass` on the stable target: it mechanically recomputed the
  OpenSpec checklist, 21-file manifest, runtime journal, context sidecar,

  zero mismatches. Before that pass, it refused to infer byte identity from an
  aggregate-only prose claim and required the lead to persist the 16 audited
  source/test hashes; the invalidated moving-target attempt is `surface_failure`,
  not a model loss. This reinforces Luna/medium as a best current route for
  bounded artifact closure when every claim reduces to paths, hashes, exact JSON
  relations, and a deterministic verifier. It does not make Luna the owner of
  the engineering or research conclusion.

- Treat API retries, quota exhaustion, completion delay, and lifecycle failures
  as surface or runtime evidence, not model-quality evidence.

## Maintenance

- Keep only evidence that changes a routing decision. One result is provisional;
  repeated comparable evidence may change a default.
- Revisit affected priors when a model revision, agent version, tool surface,
  or common task class changes. Keep unavailable models inactive rather than
  deleting their evidence.
- Edit recommendations in place and delete stale or absorbed prose. Do not
  require a benchmark, profiling pass, per-task ledger, or formal routing
  matrix.
