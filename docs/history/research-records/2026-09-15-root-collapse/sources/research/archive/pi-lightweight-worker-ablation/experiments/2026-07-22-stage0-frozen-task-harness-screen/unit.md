# Stage 0 Frozen-Task Pi Harness Screen

## Question

Across four bounded CoordExp task families, does Pi preserve first-attempt
correctness and scope compliance while reducing complete delegated-system
token or monetary cost after independent Codex verification?

## Competing Explanation

The strongest alternative is that an apparent difference is caused by a
different model, reasoning effort, provider behavior, source snapshot, prompt,
or verifier rather than the worker harness. The primary control is one
identical self-contained task packet, frozen source and evidence hashes, the
same model and reasoning level where both harnesses expose the same effective
surface, and one hidden verifier. If effective model parity cannot be shown,
the run is a capability scout only and no harness comparison is claimed.

## Primary Observation

For each arm and task, record first-attempt hidden-verifier outcome, critical
scope or scientific-semantic errors, input/output/cache tokens, provider-
reported cost, wall time, tool calls, verification time, retries, and manual
corrections. The smallest decision-changing observation is one matched
artifact-inventory task completed by both arms with an attributable result and
a complete receipt.

## Terminology

- **Pi**: the external terminal coding harness installed from the official
  `@earendil-works/pi-coding-agent` npm package.
- **Native Codex worker**: a fresh Codex Multi-Agent Version 2 thread started
  with no inherited conversation turns and only the frozen task packet.
- **Capability scout**: an execution that tests whether a worker can complete
  the task but cannot attribute a difference to the harness because a matched
  model, reasoning level, provider surface, or accounting rule is absent.
- **Complete delegated-system cost**: root preparation plus worker execution,
  independent verification, retries, and human correction under one declared
  accounting rule.
- **Critical failure**: a conclusion-changing scientific error, hidden-check
  failure, credential or isolation breach, write outside the allowed area, or
  material violation of a must-not-do constraint.

## Outline

### Task families

1. Artifact inventory for one closed research unit.
2. Source routing for one current inference configuration field.
3. Claim audit against a compact projection of a closed result artifact.
4. Deterministic aggregation from fixed JavaScript Object Notation Lines
   (`JSONL`) input.

Each worker sees only its task packet and worker-visible fixture. The hidden
verifier, another arm's answer, parent research discussion, and active
constant-dose image-breadth screen are excluded.

### Reused infrastructure

- immutable Git snapshot at commit `bb26ed613c5393255dc8784d0bbd1d122c3befd6`;
- closed individual-trajectory versus sampled-union support audit evidence;
- Pi print, JavaScript Object Notation (`JSON`) event, or Remote Procedure Call
  (`RPC`) mode only after a non-interactive containment smoke;
- native Codex `spawn_agent` with `fork_turns: none` for the comparison arm;
- operating-system process timeout and cleanup outside Pi.

### Representative smoke

Run only the artifact-inventory task first. Inspect the full worker receipt and
hidden-check result before opening the other three tasks.

### Non-goals

- no Pi extension, persistent adapter, or Codex-core change;
- no write benchmark, graphics-processing-unit access, live-run inspection, or
  active-worktree target;
- no scientific interpretation, architecture choice, or final claim delegated
  to Pi;
- no general Pi-versus-Codex claim from four tasks.

### Stop rule

Stop immediately on a credential or containment breach, a write outside the
allowed scratch root, a critical scientific or scope error, or inability to
attribute the arm because effective model parity and accounting cannot be
established. After all four tasks, stop with one bounded task-family verdict;
do not build integration in this unit.

### Rough cost

One installation verification, one containment/authentication gate, two worker
arms on the first task, then at most six additional worker executions if the
smoke passes. No graphics-processing-unit time is authorized.
