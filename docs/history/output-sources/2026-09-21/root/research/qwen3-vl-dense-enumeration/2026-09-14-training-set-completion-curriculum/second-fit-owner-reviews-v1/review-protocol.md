# Second-fit step16 physical review contract

Review one assigned image only. Output is candidate until root acceptance. Use its packet under second-fit-review-packets-v1/image-<12digit>/packet.json. Target is target-owners-complete-v3.json (228 atomic owners across11 images; six crowd annotations separate). Parent actual native step16 is parent16-v3-physical-ledger-v2/ledger.json, with root-acceptance.json and root-effective-class-decisions.json overriding class-only counters. Parent geometry-qualified coverage totals155, not identity-only161.

Inspect the original image, target and prediction overlays, and bbox context/tight crops for each distinct valid visual group. Same-image crop sheets are allowed; no multi-image montage. Every original raw prediction must survive in the decisions. An exact-signature shared crop can support multiple raw members, but those remain repeated model predictions. Different boxes on the same owner are also repeats even below IoU.95. Invalid or malformed rows can be marked invalid_output from raw parser evidence; never infer physical FP merely from invalidity or GT-unmatched status. Do not repair generated axes for credit.

Use raw physical identity AND reasonable geometry for coverage; class errors are separate. Count an owner once if any parsed-valid, reasonable row with true_unique/repeat identity supports it. Preserve every fixed owner in the missing/covered partition. Respect root overrides and geometry uncertainty. Unknowns remain unknown. Verified new objects receive pending_new IDs and reference proposals, but do not change the fixed v3 denominator without root admission.

Write exactly review.json plus any same-image evidence/validation script inside your assigned image directory under second-fit-owner-reviews-v1. Schema: second_fit_step16_owner_review.v1. Top-level fields: image_id, checkpoint_step:16, target_catalog (path and sha256), source_packet (path and sha256), status:candidate_ready, raw_row_count, decisions (flat JSON list), summary, new_owner_candidates, validation.

Each decision has prediction_id, generated_order, visual_group_id, owner_id (fixed-v3 ID, pending-new ID, or null), physical_status (true_unique/repeat/false/unknown/invalid_output), extent (reasonable/wrong/unknown), class (verified/wrong/unknown), coverage_eligible (bool), direct_CE {bbox:positive|mask,description:positive|mask}, reason, evidence_paths. Repeated physical owners never receive direct positive CE; a verified unique owner with reasonable geometry can have bbox positive and class masked. Unknown or invalid/false/wrong-extent rows have both fields masked. New candidates remain masked until root admission.

Summary: target_owner_count, covered_owner_ids, missing_owner_ids, covered_owner_count, missing_owner_count, physical_repeat_row_count, confirmed_false_row_count, physical_unknown_row_count, invalid_output_row_count, class_wrong_row_count, class_unknown_row_count, raw_stop_reason, cap_debt, parent_covered_owner_ids, retained_parent_owner_ids, lost_parent_owner_ids, newly_covered_fixed_owner_ids. Report whether the stage03 appended GT/reference repair is qualified, and identify earliest observed repeat/structural issue when possible. No all-stage pass claim. Validate all raw prediction IDs, exact group membership, coverage eligibility and set partitions, source/evidence hashes, and class/extent/mask field domains.

Scientific question: did verified absent-owner support enter natural greedy before raw errors or stopping degeneration? No training/eval/GPU, no source edits or denominator mutation. Stop after the assigned single-image review and reproducible candidate validation.
