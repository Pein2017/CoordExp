仍是共享规则的 owner。只在实际需要跨环境传输时阅读本文。

## 传输边界

代码、配置和已跟踪文档优先通过已授权的 Git 流程同步，不用文件复制覆盖。
需要单独传输的通常是 checkpoint、adapter、大型日志、预测、可视化和评测产物。
先确认实际 owner、来源实验与必要的 Git revision；同名不代表同一结果。
沿用目标 checkout 的存储位置，不再新建一套 `artifacts/<host>/` 目录规范。

先列出精确来源和目标，再做 `rsync -avhn --progress <src> <dst>` dry-run；
确认路径末尾斜杠的目录语义、包含项、冲突和大小后，才执行获准的实际复制。
大文件可按实际需要使用 `--partial --append-verify`，但它不授权追加或覆盖
一个身份不同的目标文件。来源应停止写入或有明确一致性边界。

不默认同步 `.git/`、环境、依赖目录、缓存和锁文件；不默认覆盖较新的对端
结果或删除对端文件。镜像删除需要独立的明确授权与对应 dry-run。
复制完成后验证本次实际消费者所需的内容，不把“命令退出成功”等同于
checkpoint 可加载或原历史执行可复验。

## 交付与定时任务

记录本次实际来源、目标、选择范围、结果及未解决冲突。已有日志或运行记录
足够时，不另建全量 manifest、重复 source snapshot 或每文件 SHA 台账。
昂贵、不可替代或有 identity 消费者的证据仍按其原契约校验。

定时同步是另一个明确授权的任务：先约定目录范围、覆盖/删除规则、日志
位置和失败处理，再部署对应调度。本文不创建 cron、timer 或后台同步。
