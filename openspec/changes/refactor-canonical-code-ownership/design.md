## Context

See proposal.md for the authorized scope and baseline. The audit found real consumers of both annotation entrypoints, two parallel research embedding implementations, probe-to-ancestor mechanism imports, and concentrated session/state/packing/merge protocols. The checkouts are independently versioned capabilities, not a release ladder. Their initial tracked source is clean; other Codex processes and services remain present.

## Goals / Non-Goals

**Goals:** one discoverable implementation owner per local capability; direct current consumers; explicit scientific policy inputs; reviewable transaction/lifecycle boundaries; behavior-proportionate evidence and local commits across all three trees.

**Non-Goals:** package distribution, global namespace migration, branch homogenization, changing losses/labels/default recipes/metrics, rewriting sealed evidence, creating new scientific experiments, or maintaining transition-only internal API identities.

## Decisions

1. **Source-level adoption, not live cross-worktree imports.** Reuse the current infrastructure YAML-document mechanism where its semantics fit, retaining distinct train/inference merge policies and path authorship. Other adoption requires a named actual consumer and recorded semantic comparison. Each tree remains runnable without importing a sibling checkout.
2. **Explicit mechanism inputs.** Composition, export, exact-history replay and optimizer/tensor snapshots belong to existing `src.qwen`, `src.adapters`, `src.training` or artifact owners according to their computation. The calling probe owns checkpoint binding, policy, cohort, source release, budget and interpretation. Avoid a generic experiment Context or registry; do not move an entire historical experiment into src.
3. **One embedding implementation.** Consolidate selected-token data/validation/installation/serialization while representing tying and wrapper selection explicitly. Preserve base and delta dtype, parameter aliasing, tensor keys and admitted historical payloads. Any observed selection discrepancy must be preserved as an explicit boundary or fixed as a separately evidenced bug, not silently normalized.
4. **Separate values, algorithms and resource protocols.** Refactor training model assembly from session lifecycle; state records/codecs from authenticated publication/restoration; packing values/cursors from algorithms; shard admission from cross-shard reconciliation and final publication. Keep each transaction/close/failure protocol locally reviewable. Structured stage results replace repeated dictionary interpretation, not a bag of twenty unrelated fields.
5. **Reviewed bank remains a scientific subsystem.** Separate records/schema, family admission, assembler and storage. Existing family policies and holdout identities stay specific to the existing bank; they do not become universal research rules.
6. **UI-neutral dataset authority.** Both application adapters consume the same neutral core. SQLite draft/task projection remains distinct from canonical working JSONL/journal authority. Extract record/codec/index responsibilities without splitting the lock/reattest/journal/replace/fsync/terminal protocol into arbitrary services.
7. **Persisted paths are different from internal aliases.** Migrate current imports directly. Where pickle or payloads embed old module identities, retain a bounded explicit reader mapping or required compatibility surface and prove old fixtures still load. Frozen fixtures and historical outputs are never regenerated to admit changed source.
8. **Three bounded implementation packages, one writer per checkout surface.** Main worker owns annotation source/consumers/tests; infra worker owns session, state, packing and merge; research worker owns probe mechanisms, embeddings and bank. The coordinating lead owns this plan, cross-tree adoption after package stabilization, source review and commits. Ephemeral Codex exec jobs are task-bound workers, not persistent research lead threads. Workers do not stage/commit/push or modify sibling trees; no shared environment changes. Main generated evidence uses `.local/qualification/canonical-code-refactor-20261006/`; other trees use `outputs/qualification/canonical-code-refactor-20261006/`. Source validators belong under maintained tests/scripts, not outputs.

## Risks / Trade-offs

**Verified external-consumer exception:** `/data/CoordExp/label-studio` is a separate clean Git repository, not one of the three authorized branches. Its deployed `coordexp_refinement` modules import `src.label_studio_coco_refinement.store`, and its runtime factory binds `WorkingDatasetStore.bootstrap` without a task-index binder. Retain a narrow application adapter at that path: re-export the exact consumed values and subclass the neutral store only to supply the Label Studio bootstrap binder. All publication/recovery methods remain inherited, identical and uniquely owned in `src.working_dataset`. Current main callers import defining owners directly. This is a real product contract, not a speculative internal shim; retiring it requires explicit adoption in that separately versioned consumer. No vendor repository or live service is changed.

- Shape-preserving output can hide wrong gradients/aliasing: compare autograd paths, finite differences, trainability, dtype and save/load identities.
- Structural moves can invalidate source-bound qualification: new runs use fresh identity; old receipts are immutable and not treated as launch grants.
- Session assembly or exception order can change distributed behavior: use the smallest real multi-rank slice that observes order, failure convergence and affected optimizer/RNG/cursor state.
- Large modules can become an import maze: require real consumers and cohesive boundaries; reject new modules that only forward or collect unrelated fields.
- External writers can appear: check current Git and exact target content before writes/commit; preserve anything outside the package and report overlaps.

## Separately evidenced behavior repair

The first native two-rank slice exposed a pre-existing multimodal kwargs collision: text packing offsets reached Qwen3VLVisionModel, whose attention already computes its own varlen offsets. The dedicated infrastructure fix filters only the four text varlen kwargs at vision-model entry, before checkpoint blocks capture them; text packing, caller tensors and native vision boundaries stay intact. Scoped hooks are removed on success and exceptions. Actual tiny-model forward/backward, checkpoint-recompute and wrong-hook/global-drop controls distinguish this fix from a structural move. It is committed separately, with no library installation, global registry replacement, science-policy change or tolerance relaxation. See verification.md and infra-repair-report.md for RED/GREEN and native continuation evidence.

## Migration Plan

First exercise a real caller-to-consumer slice inside each independent package. Migrate current consumers as mechanisms move, then retire the replaced implementation and transition-only tests. Run affected CPU/tensor and storage/fault tests early. Run actual checkpoint/backend qualification for changed model paths and minimal multi-rank qualification for distributed-sensitive lifecycle changes; use eight ranks only for an eight-rank contract. No long training or scientific comparison is authorized.

Freeze each candidate before final checks. The lead reviews changed protocol boundaries and reuses unchanged worker evidence, runs required cross-package consumer checks, reviews whitespace and a redacted credential scan, and creates explicit local commits. A source-backed not-applicable ruling must explain the actual caller/contract evidence; implementation difficulty is not a scope exemption. Final verification records commands, exit status/counts, source identity, evidence paths, unchanged behavior, any separately identified fix and outstanding blockers. Code rollback uses Git; published historical data/state is not overwritten or resealed. The change remains available for the user's independent Codex verifier rather than being prematurely archived.
