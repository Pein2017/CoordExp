## Context

See proposal.md for motivation. `VllmDoraRollout` owns a spawned TP=1 engine per HF rank and already transfers approximately 88.6 MB of selected trainables through one synchronous RPC. Refresh updates fixed buffers, DoRA scales, current median factors, and the cache before acknowledging a new snapshot. The current API hardcodes greedy selection and duplicates normalized log probabilities into both trace fields.

## Goals / Non-Goals

Expose one reusable resident acquisition path with current-version weights, seeded full-support sampling, and genuine paired selected-action probabilities. Keep HF replay differentiable through the current median factors. Do not add asynchronous stale-policy training, an optimizer framework, speculative decoding support, installed-package patches, or a new checkpoint format. Existing frozen runs remain on their released source and backend.

## Decisions

1. **Shared policy and replay owners.** Move median policy arithmetic and its HF model binding to `src/qwen/coordinate_policy.py`; preserve the probe import as a compatibility re-export. A pure tensor helper computes norms/factors from the selected BF16 base rows plus independent FP32 deltas, using FP64 norms and lower median. HF factors remain graph-connected; vLLM snapshots them at refresh. Shared coordinate scaling preserves the input score dtype. Move the already-qualified singleton prompt placeholder context into `src/qwen/native.py`, keeping the experiment import as a re-export and preserving its exact scope/validation. This removes duplicate arithmetic and experiment-owned replay knowledge without merging model loading or research losses.
2. **Existing synchronous ownership.** A caller completes generation, performs HF replay/backward/optimizer update, snapshots trainables, waits for refresh/cache-reset acknowledgement, and only then acquires the next version. Failed refresh cannot publish its requested identity. Generation binds the acknowledged snapshot. No background copy or stale-version overlap is introduced.
3. **Opt-in paired traces in repository code.** Add `src/qwen/vllm_trace.py` with a worker extension and sampler hook. `compute_logits` publishes one transient pre-median logits clone only while tracing. The existing sampler selects actions; the hook reduces that clone to selected raw likelihoods and retains the sampler's actual normalized likelihoods. Release full logits in `finally`. Retain only token IDs, action positions, and probability pairs. No extra model forward, per-step vocabulary history, or vocabulary-sized host transfer is allowed.
4. **Associate by live request metadata.** Sampling parameters carry caller request ID, snapshot, and budget. Resolve each sampler row through current internal request state, excluding discarded prefill rows. Action position is computed from scheduled/computed tokens minus original prompt length. Blocking generation finalizes against emitted IDs, requiring complete unique positions and matching tokens; verified async post-EOS suffixes are excluded and counted. Never infer association from UUID text or a persistent batch row.
5. **Narrow sampling support.** Preserve greedy defaults; opt in to per-request seeded temperature-one sampling with unrestricted support and neutral penalties. Preserve actual EOS and PAD before EOS. Reject unsupported policy controls and tracing with speculative decoding. The legacy exact-prefix full-score diagnostic remains separate from paired trace acquisition.

Alternatives considered: moving median scaling into an upstream logits processor still requires a second channel and complicates batch bookkeeping; replacing a model runner or sampler duplicates upstream scheduling. The local extension/hook preserves native selection and has the smallest supported seam. Current installed vLLM is 0.29; live runner source, rather than stale graph excerpts, defines its request metadata boundary.

## Risks / Trade-offs

- Async sampling can run beyond final EOS and prefill can sample discarded rows. Counterexample tests cover both, along with row compaction, mixed budgets, PAD, missing/duplicate actions, and stale identities; native qualification checks the actual runner.
- One raw logits batch adds approximately 1.8 MB for three FP32 rows at 152k vocabulary, plus selected-scoring workspace; retained traces are O(total actions). Trace-off calls must retain no trace buffers.
- HF and vLLM differ numerically. Measure raw and policy replay differences without promising exact tokens, exact gradients, or a numerical acceptance threshold. Identity, action alignment, finite values, and cache/version correctness are hard invariants.
- Existing HF sampling must use the same intended median policy and literal sampled action IDs. Backend selection remains opt-in; no implicit change to ongoing research.

## Migration Plan

Implement in the isolated worktree based on `249b9b0`. Characterize frozen arithmetic, fix the paired-channel/PAD counterexamples, and run focused CPU checks. Extend the existing technical runtime probe for one real learning update and acknowledged next-version acquisition, recording startup, generation, transfer, trace retrieval, model replay, tokens, memory, and cleanup. Bind its exact small run before launch; no scientific quality study is needed. Integrate only after canonical frozen-run holders release the affected source. Rollback is caller selection of the unchanged HF backend or previous commit.

## Bounded technical qualification

Use one two-rank invocation, current shared step-2444 anchor, images 1584/2299/2685, stride assignment 2/1, and per-image budgets 64/64/32. Acquire HF greedy/sample and resident greedy/sample at version zero. Reuse three differentiable HF replays of the first at most 32 vLLM sampled actions for both likelihood comparison and a technical image-mean negative policy-log-likelihood update. Backward each image loss divided by three, SUM gradients once after local work, clip, and update once; require identical updated trainable snapshots across ranks. Refresh synchronously, acquire resident greedy/sample at version one, then restore the original trainable snapshot and verify a 16-action greedy prefix per image before restoring updated HF bytes and closing engines.

The ceiling is 21 generation requests / 1,008 emitted actions, three replay forwards/backwards / 96 supervised actions, one logical optimizer update, and four resident refreshes total. Backend startup profiling/capture is recorded separately. No requested warmups, duplicate diagnostic forwards, checkpoint exports, or scientific metrics. This bounds implementation qualification, not full-study performance. Identity, aligned finite paired traces, and cleanup are required; numerical HF/vLLM gaps are observations. A failed invocation preserves evidence and is repaired only within this technical package; replacements require a fresh output/source binding and reconciliation of the prior processes.
