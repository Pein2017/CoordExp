# Routing evaluation for resumable support shards

This is task-shaped routing evidence, not a matched benchmark or a global model
ranking. Acceptance came from executable checks, lead integration, and an
independent fixed-tree audit rather than worker completion prose.

| Route | Narrow lane | Disposition | Best current use | Observed boundary |
| --- | --- | --- | --- | --- |
| Luna/high | Source inventory and command discovery | `accepted_first_pass` | Bounded read-only scouting with exact paths and hashes | The lead still owns interpretation and adoption. |
| Luna/max | Deterministic source-binding leaf | `accepted_after_correction` | A localized depth gap whose complete output is decided by hash/schema tests | One correction was needed for volatile-field exclusion; max effort did not establish fitness for durability or lifecycle ownership. |
| Terra/high | Cross-file adapter integration | `accepted_after_correction` | One stable integration seam with an explicit lifecycle and compatibility matrix | Initial work omitted lifecycle-critical execution/compatibility closure; lead integration remained necessary. |
| Sol/high | Fixed-tree standards and intent audit | `accepted_first_pass` | Silent-correctness, provenance, and pre-publication counterexamples after code freeze | Its correct initial verdict was `HOLD`; target acceptance required implementation repair and a fresh GPU receipt. |

The resulting policy calibration is:

- Route Luna/max only when ordinary Luna depth has a demonstrated local gap and
  the same deterministic verifier still decides the entire lane.
- Do not use effort escalation to turn a crash-consistency, compatibility, or
  multi-stage lifecycle seam into a Luna-shaped task.
- Give Terra/high a single enumerated integration owner surface, including
  success, absence, failure, continuation, publication, and old-compatibility
  paths in the initial acceptance matrix.
- Reserve Sol/high for consequential counterexamples and research-versus-infra
  boundary review; count a reproducible `HOLD` as reviewer success, not target
  success.
- Freeze the implementation and runtime tree before fixed-tree review or a real
  mechanics smoke. Any later runtime edit supersedes that evidence and requires
  a fresh bound receipt.

Evidence anchors:

- `cpu-equivalence-v5.json`: deterministic uninterrupted versus resume receipt
  equivalence and unchanged-merger acceptance.
- `gpu-sigterm-resume-v7.json`: current-tree real external SIGTERM, exact
  continuation, durable-byte preservation, terminal mechanics, and GPU release.
- `compatibility-gate-v4.json`: current unchanged merger and active downstream
  regression acceptance.
- `standards-audit.json` and `intent-contract-audit.json`: independent final
  dispositions after repair.
