# Sol / Luna trial on the actual next experiment

The user explicitly reopened Sol and Luna and subsequently requested Luna-max
as the usual setting. Astra remains the lead; no new Astra child was used.
This is a task-specific quality observation, not a matched model benchmark.

## Sol-high: useful draft, not accepted unchanged

Owned read-only executable design and source navigation. Useful contributions:
separate one shared model per arm from cross-arm checkpoint contamination;
identify EOS-adjacent append as a weak composition stratum; inspect native
generation and checkpoint reuse seams; request target geometry incidence.

The lead did not adopt several unsupported changes: requiring the literal
toy's a/b/c/d/e interleaving, reclassifying absence of a same-class prediction
as proven enumeration omission, making invariant bipartite row assignment a
new rejection gate, stopping acquisition after8 successes instead of exhausting
the fixed24, or replacing actual student duplicate acquisition with only a
fixed duplicate bank. These differ from the active question or accepted
signal boundary. Final-b assignment is retained as a diagnostic; actual
owner-set metrics remain decision-owning.

Disposition: candidate design partially useful; **not a standalone accepted
research/launch plan**. No Sol-written producer was launched.

## Luna-high: inventory arithmetic rejected and corrected before GPU

Its counts, split membership and missing-owner identities agreed with a lead
read of the native consumer:27 eligible exact-two images,24 selected. However,
ranking area mixed units: image184490 owner116077 used norm999 bbox area
`442*553` divided by pixel area `1152*864`, giving0.2455733185442387.
Native pixel conversion gives bbox `[0,385,509,863]` and fraction
0.24444404256687244. This invalidated that delivered geometry statistic.

The lead preserved both original files as
`candidate-inventory.luna-high-rejected.{json,md}`, recomputed all candidates
from the current consumer via `inventory.py`, and verified the resulting
selection. **The24 selected IDs and their order happened to remain unchanged**;
no model call used the erroneous inventory. Initial `records`/`candidates`
schema and primary exact-two scope were also reconciled before launch.

Disposition: raw inventory **not lead-accepted**; corrected lead recomputation
is the frozen producer input. The finding is a real units error, not evidence
that the executed cohort changed.

## Luna-max: focused CPU counterexamples accepted

Owned only `test_admission.py`; no producer edit, GPU call or broad audit.
Six tests exercise exact row boundaries, replayed/forced/free accounting,
EOS corruption, wrong-source suffix rejection, native geometry, strict
class/GT-independent `>0.95` repeats, and the preserved inventory counterexample.
The lead inspected the assertions and reran the suite:6 passed. The tests use
the real tokenizer/parser/scorer, not a mocked model forward.

Disposition: **lead-accepted for this bounded CPU test surface**. This does not
prove that Luna-max would design the experiment correctly or establish model
generation/training correctness. Live acquisition has its own receipts.

## Routing decision

Use Luna-max for subsequent bounded, checkable work. Sol remains useful for
source-backed drafts, with the lead owning semantics and acceptance. One task
per role, different scopes and evolving briefs do not support a general
intelligence, price/performance or latency ranking against Astra.
