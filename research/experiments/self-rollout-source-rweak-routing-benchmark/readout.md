# Same-input model-routing benchmark: provisional decision

**Lead recommendation: temporarily withdraw Sol from default routing for these
tested task classes, retaining manual comparator/fallback availability.** This
supports the user's temporary policy, not universal retirement, deletion of
capability, or a claim about a future model family. No global configuration or
skill file was changed by this study.

Both engineering candidates and both uncontaminated scientific answers ultimately
passed the common acceptance criteria. Astra reached usable results sooner and
at lower measured accepted-chain API cost in these two task comparisons. Sol
also contributed a real runtime improvement and useful scientific sensitivity;
its results are not discarded simply because it took longer.

Elapsed means first task start through final worker completion, including
orchestration, review, correction and waiting, not API compute time. The Sol
scientific lifecycle is a calendar envelope, not a sum double-counting overlapping
attempt intervals. Root acceptance follows independent replay/review, not the
worker's completion marker. Engineering had GPU scheduling waits; these elapsed
figures must not all be attributed to model generation speed.

The engineering question and immutable sources/fixtures were identical, with
fresh contexts and isolated owned paths. Both replayed the four shared fixtures
at B1/B4 under both recipient checkpoints, including exact native diagonals,
crossed tokens, parser/matcher persistence and per-request budget/EOS behavior.
Root also verified cross token/parsed identity between the two implementations.
Only one accepted implementation ran the formal32-case panel.

- **Astra/low engineering:** passed its first submitted qualification path;
  no root-requested semantic correction. Candidate's own pre-submission fixes
  and checks are included in its receipt cost. Its earlier acceptance allowed
  the scientific panel to proceed while Sol finished.
- **Sol/xhigh engineering:** one bundled native-stop serialization correction
  (`sampled_eos` versus native `im_end`) and the already-required real saved
  consumer fixture. Then passed the same real acceptance. Its warm model reuse
  and batching completed equivalent qualification in**177 GPU-s versus341**;
  this is a genuine runtime advantage, despite later end-to-end acceptance.
- **Astra/medium science:** first answer accepted. It supplied explicit
  interaction, direct-replacement, transitive-matching, internal-state and
  gradient counterexamples, and a useful category/localization alternative.
- **Sol/max science:** the first attempt's broad recursive search exposed peer
  answer excerpts; it self-reported, wrote no answer, and was superseded. A fresh
  isolated retry then supplied a useful leave-one-cap-case sensitivity. Root

  the corrected negative-screen bound and answer passed.

## Decision and limitations

For the current default, the measured advantage is Astra's lower accepted-chain
API cost and shorter end-to-end lifecycle without losing acceptance quality in
these two tasks. Keep Sol available for explicit comparisons/fallback; its warm
runtime result and cap sensitivity show why this is not a claim of incapability.
Revisit the routing prior when task evidence or model versions change. No
additional benchmark, training, or general-purpose routing framework is warranted
to close this request.
