# Research ownership and evidence

The index routes decisions; questions own current scientific interpretation;
story summarizes the argument; assets identify reusable data/model inputs; the
catalog owns complete historical retrieval. Do not copy current status into
memories, handoff or progress ledgers.

## Current versus distilled units

A new live unit may contain its question, explicit estimand/contrast, population,
checkpoint/config/input identity, cost and stopping boundaries, state and results.
It is not a package-per-run requirement. A closed phase is distilled to its topic:
strongest positive, strongest counterexample, bounded inference, unanswered
question and reopen condition, artifact locators and exact Git recovery context.
Then delete its redundant operation records and dead implementation closure.
Do not create unit tombstones or another archive directory.

Catalog v2 `tracking=distilled` needs no live directory. It retains the original
status/evidence labels, summary/boundary, topic, full commit and original reading
path/hash. Its continuation is `unsupported_historical`. A new `tracking=current`
row instead owns an existing record_root, reading_entry and state. Closed does
not mean scientifically negative; invalid is not null; accepted partial evidence
is not a completed full comparison.

## Claims and identities

State the experimental unit and denominator before its metric. Keep token margin,
conditional row likelihood, free complete-row realization, trajectory behavior
and physical-owner coverage separate. Keep gains, source-owner losses, duplicates,
invalid geometry, unmatched predictions and EOS/cap debt separate. Distinguish
annotation absence from a physical negative and shared ambiguity from arm-specific
error. Never pool incompatible cohorts or label versions.

Questions cite catalog IDs; each decision-bearing claim must have a recorded
artifact or exact historical Git source. Historical locators are not verified
current existence unless freshly checked. A file being readable cannot grant
permission to continue its run. Missing/changed/unverifiable execution source
must fail closed; current qualification produces a new identity.

Decision-bearing current execution uses a clean Git commit/tree and explicit
source paths plus separately bound data/config/runtime context. No dirty-source
archive is maintained. Do not rewrite a historical receipt or relax its hash to
fit new code. CPU tests do not prove real-model/GPU numerical parity.

## Validation and deletion

`python -m scripts.check_research_knowledge check` validates current links,
catalog schema, claim references and Git recovery hashes. Deleting a capability
includes its exclusive tests/configs/launchers; tests alone do not justify code.
Keep independently useful readers, evaluators, controls and integrity checks.
External outputs, model packages, datasets and active unrelated work are not
repository-cleanup targets. Git stores detailed historical recovery.
